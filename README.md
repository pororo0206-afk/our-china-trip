# V6 · 대표 사진을 깔끔하게 직접 바꾸기

- 기본 여행 페이지에는 **사진 편집 아이콘이 없습니다.** 상단의 작은 `···` 메뉴에서 `✎ 대표 사진 편집`을 누르면 카드에만 작은 편집 아이콘이 나타납니다. 수정 후 `✓ 편집 완료`를 누르면 평소 화면으로 복귀합니다.
- 사진 변경 창에서 **휴대폰·PC 사진 업로드** 또는 **직접 이미지 URL**을 선택하고 `대표 사진 저장`을 누르세요. 자동 변경이 아니라 직접 선택한 대표 사진만 변경됩니다. `↶ 기본 이미지로 복원`도 가능합니다.
- **현재처럼 Supabase를 연결하지 않은 상태:** 누구나 자기 브라우저에서 `사진 편집`을 볼 수 있지만, 변경 결과는 **해당 기기에서만** 보입니다. 사진 파일은 IndexedDB에 저장되므로 브라우저 데이터 삭제 시 사라집니다. GitHub에 다시 올리거나 친구들과 동기화되지 않습니다.
- **Supabase 연결 시:** 공개 사이트에서는 편집 기능이 보이지 않습니다. `trip_photo_admins`에 등록된 **관리자 이메일로 로그인한 경우에만** 사진 편집 버튼이 나타납니다. 사진 파일은 Supabase Storage에, 새 대표 사진 URL은 `trip_covers`에 저장되고 다른 사람이 페이지를 새로 열면 동일하게 보입니다.
- **중요:** 최초 공동 사진 편집 설정에는 추가 SQL 파일 `supabase-covers.sql` 실행과 관리자 이메일 등록이 필요합니다. `config.js`에 공개용 Supabase URL·anon 키만 입력해야 합니다. 새 파일을 배포했다고 자동으로 온라인 사진 저장소가 생기는 것은 아닙니다.
- **이미지 URL은 직접 이미지 주소여야 합니다.** `instagram.com/p/...` 같은 게시물 페이지 주소는 사진 주소가 아닙니다. SNS에 올라온 사진은 재사용 권리를 확인하세요. Storage를 공개 버킷으로 이용하므로 업로드한 대표 사진 자체는 공개됩니다.
- **GitHub Pages는 사진 편집 서버가 아닙니다.** 친구들이 모두 같은 이미지를 보게 하려면 Supabase 동기화가 반드시 필요합니다.

## Supabase 공동 사진 편집 추가 설정

1. 기존 `supabase.sql`의 메모 협업 설정을 유지합니다. Supabase **SQL Editor**에서 새 `supabase-covers.sql`을 실행합니다.
2. `trip_photo_admins`에 **사진을 편집할 관리자 이메일만** SQL Editor/Table Editor를 통해 추가합니다. SQL 파일 하단 예제를 참고하세요. 친구들은 `trip_members`에만 추가하면 노트 공유는 가능하지만 대표 사진 편집은 못 합니다.
3. Storage의 `trip-covers` 공개 버킷은 SQL로 생성합니다. 파일 업로드/수정 권한은 관리자로 제한하는 스토리지 RLS 정책이 적용됩니다.
4. `config.js`에 프로젝트 URL과 publishable/anon key를 입력하고 `index.html` 포함 전체 파일을 GitHub Pages에 배포합니다.
5. 관리자 계정으로 이메일 로그인을 하면 상단에 `✎ 사진 편집`이 나타납니다. 변경한 이미지는 새로고침한 다른 방문자에게 동일하게 표시됩니다.

## 1. GitHub Pages로 배포 (가장 간단)

1. GitHub에 새 저장소를 생성합니다. 예: `our-china-trip`.
2. 다운로드한 ZIP의 내용물을 압축 해제하고 `index.html`, `data.js`, `styles.css`, `app.js`, `config.js`, `assets/`, `.nojekyll` 등을 **저장소 최상위에 업로드**합니다. ZIP 파일만 업로드하면 웹사이트가 표시되지 않습니다.
3. GitHub 저장소 `Settings` → `Pages` → `Build and deployment` → `Deploy from a branch`를 선택합니다.
4. Branch: `main`, Folder: `/(root)` → `Save`.
5. GitHub에서 제공되는 `https://<사용자명>.github.io/our-china-trip/` 주소를 친구들에게 공유합니다.
6. 파일을 수정하고 `main`에 커밋하면 자동 갱신됩니다.

홈 화면에 추가하면 앱처럼 실행할 수도 있습니다. 오프라인에서도 일정표·자체 제작 이미지·동선 개략도·로컬 메모는 표시됩니다. 고덕지도·SNS 링크·공동 메모는 네트워크 연결이 필요합니다.

브라우저 내에서 동작하는 **완전 정적** 웹사이트이므로 GitHub Pages 배포 자체에는 데이터베이스가 필요 없습니다.

## 2. 메모와 SNS 링크

각 장소 아래 `Notes & inspiration` → `+ SNS 링크 / 메모`에서 URL과 내용을 추가할 수 있습니다.

- URL을 입력하면 Microlink에서 **공개 페이지 대표 이미지/제목**을 추출해 카드로 보여주려고 시도합니다.

- `⇩ 메모 백업`으로 localStorage 메모를 JSON으로 내보낼 수 있습니다.

### 중요한 차이: 일정 공유 ≠ 메모 공동 편집

GitHub Pages는 웹페이지를 배포하지만 데이터베이스나 서버를 제공하지 않습니다. 친구들이 **서로 추가한 SNS 링크와 메모를 모든 기기에서 보려면** 아래처럼 Supabase 연동을 추천합니다.

## 3. Supabase로 친구 공동 메모 연동 (선택 사항)

1. [Supabase](https://supabase.com/)에서 프로젝트를 만듭니다.
2. 프로젝트 → SQL Editor에서 `supabase.sql`을 실행합니다.
3. `trip_members` 테이블에 실제 참가자 이메일을 **관리자(Table Editor)**에서 추가합니다. SQL 파일 마지막의 주석 예시를 참고하세요. **이메일 입력만으로 아무나 들어올 수 있게 설정하지 마세요.**
4. Supabase → Authentication → URL Configuration에서 **배포된 GitHub Pages URL을 Redirect URL**로 추가합니다. 예: `https://YOURNAME.github.io/our-china-trip/**`.
5. Authentication → Email을 활성화합니다. 이메일 로그인은 매직 링크를 이용합니다. 서비스 메일 전송 한도/템플릿 확인 권장.
6. Supabase → Project Settings → API에서 Project URL과 **publishable key 또는 anon key**를 가져옵니다.
7. `config.js`에 다음과 같이 입력 후 GitHub로 올립니다.

```js
window.TRIP_CONFIG = {
  supabaseUrl: 'https://your-project.supabase.co',
  supabaseAnonKey: 'sb_publishable_... 또는 anon JWT'
};
```

> **보안:** `service_role`, secret key는 절대로 프런트엔드 파일이나 GitHub 저장소에 입력하지 마세요. Supabase anon/publishable 키는 프런트엔드용 공개 키이며 **실제 권한은 `supabase.sql`의 RLS 정책이 제한**합니다.

8. 친구가 사이트에서 `로그인`을 눌러 자신의 등록 이메일로 매직 링크를 받으면, 장소별 SNS 노트가 공동 DB에 저장됩니다. 기존 이 기기 메모는 로그인 팝업의 `이 기기의 기존 메모 공동 공유` 버튼으로 이전할 수 있습니다.

참고: 서로 다른 기기에서 내용을 **즉시 푸시로 자동 갱신하는 realtime 구독은 포함하지 않았습니다**. 페이지를 다시 열거나 새로고침하면 최신 공동 메모를 가져옵니다. 초기버전에서 가장 관리하기 쉬운 방법입니다.

파일을 직접 더블 클릭해서도 일부 기능은 작동하지만, 브라우저에 따라 로컬 파일 보안 정책으로 외부 미리보기가 막힐 수 있습니다.

```bash
python3 -m http.server 8000
```

브라우저에서 `http://localhost:8000`을 엽니다.

## 확장하면 좋은 기능

- **Supabase Storage:** 친구들이 직접 사진을 올리도록 사진 업로드 기능을 추가하려면 접근 정책을 설정한 Storage 활용.
- **Google Sheets:** 마트 구매 목록·공동 예산·정산을 함께 관리할 때 유용. 민감 정보는 공개 문서로 두지 않기.
- **GitHub Issues / Discussions:** 맛집 후보 투표, 일정 제안. 단, 댓글 작성자에게 GitHub 계정이 필요할 수 있음.
- **Amap(高德地图) JS API:** 중국 내 현지 지도가 최우선이라면 API 키와 요청 보안 설정/프록시가 필요한 별도 통합 권장. 현재 사이트의 고덕지도 장소 링크는 키가 필요 없습니다.
